Technical roadmap · v1.0 source

A local desktop app, end to end

FrameForge ships as a Windows installer. The Rust core, the measuring tool and the TabPFN engine all run on the player's PC. No server is part of the product. This page describes what's in the source today, how it's built, and what has to happen before a public release.

01 · User flow

What the player does

Install

Run the installer. It bundles WebView2, PresentMon and the AI engine, and adds the user to "Performance Log Users". Restart once.

Welcome tour

Three screens: what FrameForge does, how it keeps you safe, and that it runs offline.

Pick game + goal

Smoothest / Balanced / Best looking, plus a minimum picture-quality slider.

Play & press F9

The app launches the game through Steam. The player goes to the test spot and presses F9. Repeat per test.

Review & apply

Confirmed before/after numbers and a list of changes. "Use these settings" or "Put my original settings back".

02 · Architecture

Three local processes, one installer

The UI only talks to the Rust core over Tauri IPC (no shell, HTTP or file-system plugins are exposed). The core starts PresentMon and the engine as hidden child processes.

Tauri app (Rust) · app/src-tauri

hardware.rsCPU/RAM through sysinfo. GPU name and VRAM from the Windows display-adapter registry. Live NVIDIA temp/VRAM through nvidia-smi.
adapters.rsLoads game support JSON files. Finds Steam libraries (registry + libraryfolders.vdf), install folders and settings files.
configio.rsINI / Valve KV / JSON read and write, atomic writes, backups (oldest always kept). Unit-tested.
benchmark.rsRuns PresentMon for N seconds, parses frame times, computes average FPS and 1% low, checks the temperature every 2 s. Unit-tested.
session.rsTest loop, read-back check, two-run confirmation, always restores the original.
store.rsOne JSON file with preferences, results and crash-recovery markers.

Smart Tuner · app/engine

frameforge-engine.exePython + TabPFN frozen with PyInstaller (--onedir). Model checkpoint bundled. JSON lines on stdin/stdout.
Offline by constructionHF_HUB_OFFLINE=1, telemetry off, and socket.connect patched to raise inside the process.
Fallback: Basic tuner (Rust)Used if the engine is missing, fails to start, or returns an error. Fits a frame-time model and keeps the session going.

Bundled tools & UI

PresentMon.exeIntel, MIT licence. Uses Event Tracing for Windows. No injection.
UI · app/uiPlain HTML/CSS/JS, system fonts, strict CSP (default-src 'self'). No external requests.
NSIS installer hooksAdds the user to SID S-1-5-32-559 (Performance Log Users, language-independent). Stops any leftover trace on uninstall.
Data folder%LOCALAPPDATA%\app.frameforge.desktop\: results, backups, logs.
03 · Session logic

How one session runs (session.rs)

Search phase

1. Close the game. Back up its settings file and record crash-recovery markers.

2. Test 1 measures the file untouched, so the baseline is exactly what the player has.

3. Each later test: write the settings, launch through steam://rungameid, wait for F9 (registered only while waiting), warm up, capture 40/60/90 s, close the game.

4. Re-read the file. If any value was reverted, the test isn't counted. Two reverts in a row end the session with an explanation.

5. Ask the tuner for the next settings, or stop.

Confirmation & result

6. Choose the best run that was counted, didn't overheat or nearly fill VRAM, and meets the quality floor. Score = min(FPS, target) + 0.5 × min(1% low, target), where the target comes from the goal and the refresh rate.

7. Measure the winner and the original once more. Final numbers are two-run averages, and noise = the largest same-settings difference.

8. A gain is only reported when it's bigger than max(3%, noise). Otherwise: "already about as fast as it gets".

9. Restore the original file. New settings are written only when the player clicks "Use these settings".

04 · Smart Tuner

Constrained Bayesian optimisation with TabPFN

# app/engine/frameforge_engine.py (core of suggest())
n == 1   → prior guess: greedily lower the setting with the best cost-per-quality-point ratio
           (from the game support file) until the quality floor is reached
n < 4    → explore: the allowed candidate most different from everything tested
n ≥ 4    → TabPFNRegressor (bundled checkpoint, CUDA if available else CPU)
             context  = measured tests  (features: setting levels, prior cost, quality)
             predict  = 16/50/84% quantiles of FPS and 1%-low for ~4,000 candidates
                        that meet the quality floor
             score    = expected improvement of  min(fps,T) + 0.5·min(low,T)
             stop     if n ≥ 6 and (EI < 1.5% of best  or  P(beat best by 1.5%) < 8%)
unsafe runs (too hot / VRAM full) stay in the context with penalised values

Why the first steps aren't AI

With 1–3 measurements, any model is mostly guessing. A prior guess and a diversity step give TabPFN informative data first.

Predictions never reach the result

The engine only picks the next test. Every number shown as a result is measured by PresentMon.

Graceful fallback

Any engine error (missing file, timeout, invalid reply) switches the session to the Rust Basic tuner. The UI shows which tuner is active.

05 · Game support files

One JSON file per game

In resources/adapters/. Adding a game means writing a file, not changing code. Each file has: Steam app id, executables, settings-file paths with placeholders, and per setting: label, plain help text, option values, a relative cost and a visual-weight prior.

GameSettings fileFormatSettingsStatus
Counter-Strike 2{STEAM}\userdata\<id>\730\local\cfg\cs2_video.txtValve KV10unverified
Palworld%LOCALAPPDATA%\Pal\Saved\Config\Windows\GameUserSettings.iniINI (Unreal scalability groups)10unverified

"Unverified" means the keys and values follow the documented file formats, but we haven't yet confirmed on current game builds that the game honours every one. The cost and quality numbers are hand-set priors, used only to rank candidates and estimate picture quality. They're never shown as measurements. Built-in guards: if most keys are missing from the file, the session refuses to start. If the game reverts values, tests aren't counted.

06 · Safety design

Guarantees and their limits

GuaranteeHow it's implementedLimit
Original settings come backBackup before the first write. restore_active() runs after every session outcome and when the window closes. Markers in the store trigger a restore on the next start after a crash.If the PC loses power mid-write, the atomic temp-file + rename write limits the damage to the temp file.
No misleading resultsRead-back after each test. Refusal on key mismatch. Two-run confirmation and a noise threshold.Large changes in the player's route between tests still add noise. The app asks for the same spot and the same movement.
Temperature limitnvidia-smi every 2 s. The capture is killed above the limit and the run marked unsafe.NVIDIA only. AMD support (ADLX) is planned.
No game interferencePresentMon/ETW only. Settings written while the game is closed.Anti-cheat behaviour can't be guaranteed. Offline testing only.
No data leaves the PCNo network code in the Rust core or UI. Engine socket guard. CSP blocks external requests.The installer itself is downloaded once.
07 · Build & release

From source to installer

Automated in .github/workflows/release.yml on a Windows runner. The same steps work by hand:

# 1. Rust unit tests (config read/write round-trips, frame-time parsing, value matching)
cd app/src-tauri && cargo test --release

# 2. Offline AI engine: downloads TabPFN weights ONCE at build time, freezes, smoke-tests offline
pip install -r app/engine/requirements.txt huggingface_hub
python app/engine/build_engine.py        # → app/src-tauri/resources/engine/

# 3. PresentMon console build (MIT) → app/src-tauri/resources/tools/PresentMon.exe
#    CI picks the latest *-x64.exe asset via the GitHub API and logs its SHA-256

# 4. Installer (NSIS + MSI, WebView2 offline installer embedded)
cargo install tauri-cli --version "^2" --locked
cargo tauri build

Not done yet: code signing (an unsigned installer triggers Windows SmartScreen) and app icons (src-tauri/icons/, generated with cargo tauri icon).

08 · Validation

How we'll prove it works before claiming it

V1

Adapter verification

For each game and current build: change each setting via FrameForge, start the game, confirm the in-game menu shows the value, and confirm FPS responds. Mark "support": "verified" only then.

V2

Measurement repeatability

Same settings measured 5× per game on 3 PCs. Publish the run-to-run variation, which sets the minimum gain we can honestly report.

V3

Tuner comparison on real data

Record exhaustive sweeps (hundreds of configs per game and PC), then replay them offline through TabPFN-BO, GP-BO, SMAC, TPE and random search with benchmark/stress_test.py --data. Publish tests-to-95%-of-best with confidence intervals.

Decision rule: if V3 doesn't show TabPFN-BO beating GP-BO, we switch the default tuner and say so on the website. The engine interface is tuner-agnostic.

09 · Plan

Release plan

Phase 0 · Source complete

Done
  • Rust core, UI, offline engine, two game support files, installer hooks, CI workflow.

Phase 1 · First build & internal testing

Next · ~4 weeks
  • CI build. Fix compile and runtime issues on Windows 10 and 11.
  • V1 adapter verification and V2 repeatability on 3 PCs (NVIDIA, AMD, laptop).
  • Measure installer size and engine start time. Tune n_estimators for CPU-only PCs.
EXIT20 complete sessions without unrecovered settings. Repeatability published.

Phase 2 · Evidence

~4–6 weeks
  • V3 sweeps and tuner comparison. Replace the website's "not proven yet" section with measured results and raw data.
  • AMD temperature via ADLX. Code-signing certificate.
EXITPublished comparison. Default tuner chosen on evidence.

Phase 3 · Public beta

~6 weeks
  • Signed installer on the website. 5–10 verified games. In-app "report a problem" that saves a local diagnostics zip (user sends it manually, so the app stays offline).
  • Updates delivered as new installers. No auto-update service, to keep the app local-only.
10 · Risks

Known risks

RiskMitigation
Games change their settings formatRead-back and mismatch guards stop the session. Adapters versioned and shipped with app updates.
Installer size (PyTorch + model)CPU-only torch by default. Measure in Phase 1. Evaluate ONNX export if it's too large.
TabPFN slower than expected on CPUFewer ensemble members on CPU, fewer candidates. The Basic tuner is always available.
TabPFN licence for commercial distributionCheck Prior Labs' current licence terms for the model weights before the public release.
Anti-cheatNo injection. Offline testing only, and the app says so.
Player route varies between testsGuided instructions per game, warm-up, two-run confirmation and a noise threshold.
